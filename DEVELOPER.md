
## Local setup

```bash
# Clone the repo
git clone https://github.com/thefznkhan/KeepShelf.git
cd KeepShelf

# Install Node dev dependencies
npm install

# Generate icons from icons/icon.png  (first time only, or after changing the icon)
node scripts/generate-icons.mjs

# Build the extension into dist/
npm run build
```

Load into Chrome:

1. Go to `chrome://extensions`
2. Enable **Developer mode** (toggle, top right)
3. Click **Load unpacked**
4. Select the repo root (the folder that contains `manifest.json`)
5. Pin KeepShelf to your toolbar

After any source change, run `npm run build` (or keep `npm run watch` running), then click **Reload** on the extension card.

## Generating icons

The extension uses four icon sizes (16, 32, 48, 128 px) and one special `anime_logo.png`. The sized icons are generated from a single master file using a Python script.

### When to regenerate

Regenerate any time `icons/icon.png` is replaced or modified.

### Steps

```bash
# Make sure Pillow is installed
pip install pillow

# Run the generator
node scripts/generate-icons.mjs
```

This overwrites `icons/icon16.png`, `icons/icon32.png`, `icons/icon48.png`, and `icons/icon128.png` with circular-cropped versions of `icon.png`.

### What the script does

1. Opens `icons/icon.png` using Pillow.
2. For each target size, resizes the image at 4x supersampling then downscales for smooth antialiasing.
3. Applies a circular mask so the icon has rounded transparent corners.
4. Saves the result as a compressed PNG.

The Python code is embedded directly inside `scripts/generate-icons.mjs` as a string and executed via `python -c`, so no separate `.py` file is needed.

### Troubleshooting

| Problem | Fix |
|---------|-----|
| `Missing icons/icon.png` | Add your master icon at `icons/icon.png` first |
| `python: command not found` | Try `python3 scripts/generate-icons.mjs` or add Python to your PATH |
| `ModuleNotFoundError: No module named 'PIL'` | Run `pip install pillow` |

## Running tests

Tests use saved HTML snapshots from real pages to verify that parsers stay accurate as site layouts change.

```bash
npm test
```

This runs two steps internally:

1. `node scripts/build-test-parser.mjs` — builds ESM bundles for each shared parser into `dist-test/`.
2. `node --test tests/*.test.mjs` — runs all test files using Node's built-in test runner.

### Adding fixtures

Test fixtures are saved HTML files placed in `tests/fixtures/`. They are gitignored (kept local) to avoid storing third-party HTML in the repo. To add a fixture for a new site:

1. Open the target page in Chrome.
2. Save the full HTML (`Ctrl+S` or `File > Save page as > Webpage, Complete`).
3. Place it at `tests/fixtures/sitename_title.html`.
4. Reference it in your test file using `fs.readFileSync`.

## Adding a new parser source

Follow these steps to add support for a new website.

### 1. Shared parser (`src/shared/mysource.ts`)

```typescript
import type { ParsedMedia } from "./types.js";

export function isMysourcePage(doc: Document = document): boolean {
  // return true if the current URL matches your source
}

export function parseMysourcePage(doc: Document): ParsedMedia | null {
  // extract and return metadata, or null if not found
}
```

### 2. Content handler (`src/content/mysource.ts`)

```typescript
import { parseMysourcePage } from "../shared/mysource.js";
import type { ParsedMedia } from "../shared/types.js";

let current: ParsedMedia | null = null;

export function initMysource(): void {
  current = parseMysourcePage(document);
}

export function teardownMysource(): void {
  current = null;
}

export function getReadyToSave(): (ParsedMedia & { googleQuery: string; sourceUrl: string }) | null {
  if (!current) return null;
  return { ...current, googleQuery: document.title, sourceUrl: location.href };
}
```

### 3. Wire it into the router (`src/content/main.ts`)

```typescript
import { initMysource, teardownMysource, getReadyToSave as getMysourceReady } from "./mysource.js";
import { isMysourcePage } from "../shared/mysource.js";

// In init():
if (isMysourcePage()) { initMysource(); return; }

// In onNavigation():
teardownMysource();

// In the getPageData handler:
getMysourceReady() ?? ...
```

### 4. Manifest (`manifest.json`)

Add the host under both `host_permissions` and a new entry in `content_scripts`:

```json
"host_permissions": [
  "https://www.mysource.com/*"
],
"content_scripts": [
  {
    "matches": ["https://www.mysource.com/page/*"],
    "js": ["dist/content.js"],
    "run_at": "document_idle"
  }
]
```

### 5. Tests

Add `tests/fixtures/mysource_example.html` and `tests/mysource.test.mjs`. Follow the pattern in `tests/imdb.test.mjs` or `tests/goodreads.test.mjs`.

## Publishing a release

Releases are fully automated via GitHub Actions. You only need to push a version tag.

### Step 1: Update the version number

In `manifest.json`, bump the `"version"` field:

```json
{
  "version": "1.1.0"
}
```

In `package.json`, bump `"version"` to match:

```json
{
  "version": "1.1.0"
}
```

Commit the change:

```bash
git add manifest.json package.json
git commit -m "chore: bump version to 1.1.0"
git push origin main
```

### Step 2: Tag the release

```bash
git tag v1.1.0
git push origin v1.1.0
```

That is the only step you need. Pushing the tag triggers the release workflow automatically.

### Step 3: Verify on GitHub

Go to your repo on GitHub and open the **Releases** tab in the right sidebar. Within a minute or two you will see `KeepShelf v1.1.0` with:

- Auto-generated release notes listing commits since the last tag.
- `KeepShelf-v1.1.0.zip` attached as a downloadable asset.
- Install instructions in the release body.

## How the release workflow works

The workflow lives at `.github/workflows/release.yml` and triggers on any tag that matches `v*.*.*`.

```
push tag v1.1.0
    |
    v
GitHub Actions (ubuntu-latest)
    |
    +-- actions/checkout@v4          clone repo at that tag
    +-- actions/setup-node@v4        Node 20 with npm cache
    +-- npm ci                       install exact deps from package-lock.json
    +-- pip install pillow           Python image library
    +-- node scripts/generate-icons  produce icon16/32/48/128.png
    +-- npm run build                compile TypeScript → dist/
    +-- zip ...                      package manifest.json + dist/ + icons/ + README + LICENSE
    +-- softprops/action-gh-release  create release, attach ZIP, write install body
```

The ZIP contains everything Chrome needs to load the extension unpacked:

```
KeepShelf-v1.1.0.zip
├── manifest.json
├── dist/
│   ├── background.js
│   ├── content.js
│   ├── popup.js
│   ├── popup.html
│   └── popup.css
├── icons/
│   ├── icon16.png
│   ├── icon32.png
│   ├── icon48.png
│   ├── icon128.png
│   └── anime_logo.png
├── README.md
└── LICENSE
```

End users download this ZIP, extract it anywhere permanent, and load that folder via `chrome://extensions > Load unpacked`. No Node.js, Git, or terminal required on their side.

## Versioning convention

Follow [Semantic Versioning](https://semver.org/):

| Change type | Version bump | Example |
|-------------|-------------|---------|
| New site parser, new feature | Minor | `1.0.0` to `1.1.0` |
| Bug fix, parser fix, CSS tweak | Patch | `1.1.0` to `1.1.1` |
| Breaking storage format change | Major | `1.x.x` to `2.0.0` |

Tag format must be `vMAJOR.MINOR.PATCH` (e.g. `v1.1.0`) for the workflow to trigger.
